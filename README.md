# 月隐 · Moontrace v3 — 多角色版

基于你提供的 **moontrace-v2.zip** 增量更新。保留 v2 的手机布局、CH¹ 圆环、概率核心、多轮发言、PWA 与原生壳；增加角色板子、真实/自称角色分离和技能账本。

## 直接使用

| 文件 | 用途 |
|---|---|
| `moontrace-v3.apk` | 更新后的 Android 包；沿用输入包的应用 ID、签名证书，versionCode=3 / versionName=3.0 |
| `web/index.html` | 无依赖单文件网页，离线运行 |
| `pwa/` | 同步后的 PWA 静态文件；需要部署到 HTTPS 才能使用 Service Worker |
| `ios/Moontrace.xcodeproj` | 同步内置网页并更新版本号的 iOS 工程；此次未在 Xcode 中编译或真机运行 |
| `source/` | 可编辑源码、构建脚本、模型说明和测试 |
| `examples/17-role-demo.json` | 虚构的多角色、多轮技能示例，可在菜单中导入（会替换当前对局，可撤销） |
| `screenshots/` | 更新后的手机界面截图；`v2-reference` 是原包旧图 |

**先在旧版本导出 JSON 备份，再更新应用。** 新版读取旧 `version:1` 存档并升级到 `version:2`，旧角色备注不会自动变成真实身份。新本机存储使用 `moontrace-v3`；首次迁移只读旧 `moontrace-v1` 键，保留旧键供回退。旧版网页不能完整识别新版角色存档。

## 最常用的三个入口

- **圆环下方 → 角色与板子**：选择示例板子，或逐个增减角色张数；开启“使用角色配额约束”后同步人数与狼数。也可以不启用配额，只记录角色和技能。
- **点玩家 → 详情 → 角色身份**：分别填写“自称”和“已确认”。“已确认”需要二次确认，并影响底牌阵营和配额；自称不改变概率。清除真实角色时保留已确认的阵营；要一起清除，请再选择“未知”。
- **圆环下方 / 玩家详情 → 记技能**：选择使用者、角色、技能、对象、轮次和昼夜，区分“声称”和“已确认发生”。历史页可编辑、删除、撤销，药量和次数从记录重算。

发言中直接说“我是女巫”“我是骑士”等，会出现可取消勾选的**自称记录**预览；不是自动翻牌。只识别明确的第一人称自称，复杂转述请手动标记。

## 内置角色

| 类型 | 角色 |
|---|---|
| 基础 | 平民、狼人、预言家 |
| 你提出的特殊角色 | 白狼王、黑狼王、守卫、女巫、猎人、白痴、丘比特、骑士 |
| 其他常用扩展 | 梦魇、狼美人、隐狼、石像鬼、恶灵骑士、摄梦人、魔术师、守墓人、驯熊师 |

共 **20 种**内置角色，另可添加最多24种自定义角色（名字、狼/非狼底牌、技能说明）。别名支持“村民”“小狼”“猎手”“狼王”等。自定义角色只提供通用技能记录，不凭名称推断技能机制。

提供5个可编辑的示例板子：12人预女猎白、12人白狼王守卫、12人黑狼王守卫、12人骑士示例、17人多神自定义示例。**示例不是推荐的竞技平衡配置，也不代表所有平台的官方板子。**

17人示例为：5平民、3普通狼人、白狼王、黑狼王、梦魇、预言家、守卫、女巫、猎人、丘比特、骑士各1，总计17张、6张狼牌。

## 技能记账能做什么

支持查验、夜刀、自爆、守护/空守、解药、毒药、猎人/黑狼王开枪或放弃、白狼王自爆带人、骑士决斗、白痴翻牌、丘比特两人连接，以及恐惧、魅惑、摄梦、交换、墓验等21类技能/动作。

“声称”仅记录；“已确认”参与技能次数、药量与规则提醒，但**不会自动确认使用者的角色，也不会自动确认目标身份、改变生死或推进时间**。女巫银水可能是自刀狼；隐狼等查验变体也不能简单等同于真实阵营。技能和发言关系分开保留，技能连线为零权重，不覆盖发言分数。

药量和次数是“初始额度减去已记录的确认使用”，不是对真实剩余能力的观测；未录入的使用不计。删除技能会返还账本中的次数，撤销删除会恢复消耗。

可配置的提醒：守卫是否可连守、女巫同夜双药、自救范围、毒杀是否禁止猎人/黑狼王开枪、黑狼王是否能自爆开枪。也可填写同守同救、殉情、技能顺序等桌规备注。规则提醒允许人工覆盖，并随记录保存覆盖标记。

丘比特的恋人关系和玩家的第三方胜利标记独立保存。**狼底牌仍然算狼名额，即使该玩家属于恋人第三方；应用不自动判定第三方胜负。** 警长是额外标记，不占角色名额。

## 数学边界

原狼面模型不变：手工软证据分数 + 固定总狼数的条件伯努利分布 + 精确动态规划。角色层在已确认底牌约束下，把某阵营的概率按该阵营剩余角色配额分摊：

```
P_i(role r) = P_i(camp(r)) × remaining_count(r) / remaining_count(camp(r))
```

在同阵营角色可交换的假设下，每人角色概率之和为1，每种角色的全场概率之和等于该角色配置张数。确认过的角色为one-hot。自称、技能报告、投票心理不获得编造的角色似然比。这仍不是训练好的狼人杀模型，概率未经实战校准；没有角色间技能因果、第三方胜率或最优出人/夜刀求解。

## 构建与测试

```sh
cd source
python3 build.py
python3 tests/test_mobile.py    # 原功能回归；需要 Playwright + Chromium
python3 tests/test_roles.py     # 多角色/技能/手机界面回归
```

构建会同步 `web/`、`pwa/`、Android assets、iOS www。网页无外部运行依赖。

Android 的原始完整构建入口仍是 `android/build.sh`（需要原包 fetch-tools.sh 提供的工具）。本次原生 Java、resources.arsc 和 classes.dex 没有改动，因此也提供 `android/update_web_apk.py`：用已有APK更新内置网页、版本信息并以原证书重新签名，适用于**只改网页**的更新，不适用于改Java或权限。

```sh
cd android
python3 update_web_apk.py /path/to/previous.apk --out ../moontrace-v3.apk
```

该更新器需要 Python 的 `cryptography` 包，读取原包自带的 PKCS#12 格式 `.jks`。本次APK使用原签名证书和APK v2签名，已校验内容摘要、RSA签名、证书匹配、ZIP完整性、资源对齐和与网页产物一致性。见 `moontrace-v3.verification.json`。**当前环境未运行 Android SDK apksigner，也未真机安装；iOS工程亦未编译验收。**

原包提供了签名密钥 `android/moontrace-release.jks`，为方便连续升级原样保留；不要把含该文件的源码目录公开发布，发布静态站点只上传 `pwa/`。后续修改Java后应使用完整构建脚本与SDK工具验证。
